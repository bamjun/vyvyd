# 포스터 메이커 4단계 — 되돌리기·저장 이력·재연결

작성일: 2026-10-04  
상태: 로컬 구현·검증 완료 · 사용자 검토 대기

## 이번 단계의 범위

현재 초안을 되돌리는 Undo/Redo, 디스크에 저장된 버전 복원, 프로젝트별 초안 유지와 연결 복구를 추가했습니다. AI 소스 작업은 기존처럼 현재 Codex 대화에서 수행합니다. 로컬 브라우저와 실제 현재 대화의 MCP 호출로 아래 작업 흐름을 확인했습니다. 배포된 HTTPS 화면의 연결과 출력 UI는 이후 단계입니다.

| 상태 | 보관 위치와 역할 |
| --- | --- |
| 현재 저장본 | 로컬 서비스의 프로젝트 문서. 저장·Codex 수정·복원에 같은 수정 번호 검사 적용 |
| 저장 버전 | 프로젝트의 `history/` 아래 변경 불가능한 문서 파일. 소스·설정·레이어·파일 목록을 기록 |
| 미저장 초안 | 브라우저의 프로젝트별 설정 문자열과 레이어 편집 값. 화면에서는 즉시 반영 |
| Undo/Redo | 해당 프로젝트의 현재 브라우저 실행 메모리. 최대 100개 편집 단계 |
| 새로고침 복구용 초안 | 해당 탭의 `sessionStorage`. 기준 저장본·초안·확인이 필요한 저장/복원 요청을 보관 |
| 이전 입력 사본 | 버전 복원 전 초안 또는 최신 소스에 적용할 수 없는 입력을 보관. 프로젝트별 최신 사본 하나를 메모리와 해당 탭의 임시 저장 공간에 보관 |

## 현재 초안의 Undo/Redo

프로젝트 설정과 레이어 편집 값을 하나의 스냅샷으로 기록합니다. Undo/Redo는 소스 코드를 바꾸거나 서버의 저장 버전을 즉시 되돌리지 않습니다. 바뀐 초안을 확인하고 **저장**하면 새 저장 버전이 됩니다.

드래그 시작부터 마우스를 놓을 때까지의 여러 이동은 하나의 Undo 단계로 묶습니다. 방향키를 누르고 반복 이동한 뒤 놓는 동작과 여러 레이어의 순서 값을 바꾸는 한 번의 순서 변경도 묶습니다. 진행 중인 드래그의 Escape·포인터 취소·프로젝트/탭 전환은 시작 상태로 되돌리고 완료된 이력은 유지합니다.

일반 속성 입력은 입력칸에 초점을 둔 뒤 초점이 벗어날 때까지 한 단계로 묶으며, 유효한 값만 초안에 반영합니다. 새 편집을 하면 이전 Redo 분기는 지웁니다. 값이 같거나 객체의 키 순서만 달라졌다면 편집 단계로 추가하지 않습니다. 단순 저장 뒤에는 같은 소스의 Undo 이력을 유지합니다. 소스가 달라지거나 최신본을 명시적으로 채택하거나 저장 버전을 복원하면 새 소스 기준으로 이력을 다시 시작합니다.

편집 화면의 단축키는 Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z 또는 Ctrl/Cmd+Y입니다. 입력칸에 초점이 있으면 브라우저의 입력 되돌리기를 방해하지 않습니다. 버튼과 Ctrl+Z·Ctrl+Shift+Z는 실제 브라우저에서 확인했습니다. 취소 시 이력을 유지하는 규칙은 순수 자동 검사로 확인했고, 실제 포인터 취소 이벤트는 수동 검증하지 않았습니다.

## 프로젝트 전환과 초안 보관

프로젝트를 바꾸거나 새 프로젝트 화면을 열 때 현재 입력을 버리는 대신 프로젝트별 세션에 보관합니다. 같은 페이지에서 돌아오면 초안·Undo/Redo·레이어/이미지 선택·편집 모드·요청 문구를 다시 사용합니다. 프레임은 프로젝트 ID별로 따로 관리합니다.

**저장본 다시 열기**는 초안을 보존하는 프로젝트 전환과 구분합니다. 미저장 입력이나 반영 여부를 확인하지 못한 요청이 있으면 폐기를 확인한 뒤 최신 저장본을 읽습니다.

초안은 변경 후 잠시 대기해 `sessionStorage`에 보관하고 페이지를 떠날 때도 보관합니다. 설정의 빈 문자열 등 미완성 입력은 유지할 수 있습니다. 저장된 초안을 읽을 때는 문서 형식·프로젝트 ID·수정 번호·레이어 속성·이미지 참조와 대기 요청을 검사합니다. 다른 프로젝트의 내용이나 잘못된 구조는 복원하지 않습니다.

새로고침 복구용 사본에는 현재 초안만 들어가며 개별 Undo/Redo 목록은 들어가지 않습니다. 새로고침 후에는 저장 기준과 복구한 초안으로 이력을 시작합니다. 탭을 닫은 뒤의 미저장 초안 보존은 보장하지 않으므로 작업을 남기려면 명시적으로 저장합니다. 브라우저 임시 저장 공간이 부족하면 입력은 메모리에 유지하고 새로고침 사본을 보관하지 못했다는 안내를 표시합니다.

서비스가 끊기면 이미 열어 둔 프로젝트의 설정·레이어 초안을 계속 수정할 수 있습니다. 같은 탭에 유효한 초안 사본이 있으면 서비스가 중단된 채 새로고침해도 해당 프로젝트의 입력과 프레임을 복구할 수 있습니다. 서버가 필요한 미리보기 소스·이미지를 새로 불러오는 동작까지 오프라인으로 보장하지는 않습니다. 처음 여는 미보관 프로젝트, 저장·파일 추가·이력 조회·버전 복원은 서비스 연결이 필요합니다.

## 저장 확인과 재연결

저장과 버전 복원에는 프로젝트 ID, 예상 수정 번호, 요청 UUID를 사용합니다. 동일 UUID·동일 내용의 재시도는 중복 저장 버전을 만들지 않습니다. 다른 내용으로 UUID를 재사용하면 거부합니다.

요청이 시간 초과되거나 응답을 받기 전에 연결이 끊기면 서버에 반영됐는지 즉시 판단하지 않습니다. 제출한 초안과 요청 ID를 보관하고, 재연결 때 서비스의 요청 기록을 읽어 반영 여부를 확인합니다. 반영 기록을 찾으면 최신 저장본을 받아 처리하고, 찾지 못하면 같은 요청을 재시도할 수 있게 유지합니다.

요청 후 사용자가 추가로 입력한 내용이 있다면 제출한 초안과 현재 초안의 차이만 확인된 저장본에 다시 적용합니다. 저장 성공 응답이 늦게 왔다는 이유로 이후 입력을 덮어쓰지 않습니다. 프로젝트 전환 등으로 더 최신 작업이 시작되면 이전 비동기 응답이 다른 프로젝트를 선택하지 않도록 요청 대상을 확인합니다.

외부에서 더 최신 버전을 저장했을 때 내 초안이 없다면 최신본을 반영합니다. 초안이나 확인하지 못한 요청이 있으면 현재 입력을 유지하고 충돌을 표시합니다. 사용자는 최신 저장본을 다시 읽거나 자신의 변경만 최신본에 적용합니다. 저장의 수정 번호 충돌도 최신 문서를 다시 읽어 같은 비교 경로로 처리합니다.

비교 기준은 **이전 저장본·내 초안·최신 저장본**입니다. 사용자가 건드리지 않은 외부 변경은 유지하고 사용자가 바꾼 값·제거한 편집 값만 적용합니다. 새 소스에서 지원이 사라진 속성·레이어·이미지는 적용할 수 없는 항목으로 안내하고 이전 입력 사본에 보관합니다. 이후 소스가 다시 지원하면 **이전 입력 가져오기**로 현재 초안에 적용하고 확인 후 저장할 수 있습니다. 사본은 프로젝트별 최신 하나이며 과거의 모든 미저장 초안을 보관하는 기능은 아닙니다. 미리보기 소스는 현재 채택한 문서보다 미래 버전으로 앞서 가지 않도록 구분합니다.

## 디스크의 저장 이력과 버전 복원

새 프로젝트의 첫 문서부터 설정·레이어 저장, 이미지 추가, Codex 소스 수정과 버전 복원으로 정상 반영된 문서를 기록합니다. 이력 파일은 고유한 경로로 작성하고 해시와 문서 정보를 검사합니다. 준비 파일이 있어도 현재 프로젝트 문서에 함께 반영되지 않았다면 이력 목록에 노출하지 않습니다.

**저장 버전** 화면은 현재 프로젝트의 버전 목록과 선택한 버전의 이름·크기·FPS·소스/편집 값 개수를 보여줍니다. 선택만으로 현재 프로젝트나 초안을 교체하지 않습니다. 복원 버튼을 누르면 해당 버전의 소스·설정·편집 값을 검증하고 현재 수정 번호가 여전히 맞을 때 새 버전으로 저장합니다. 이전 번호로 되감는 방식이 아닙니다.

복원할 때 이후 추가한 이미지 파일은 계속 보관합니다. 컴파일·실행 검증에 실패하거나 복원 준비 중 다른 저장이 발생하면 현재 문서와 마지막 정상 미리보기를 덮어쓰지 않습니다. 복원 전 미저장 입력은 이전 입력 사본으로 보관하며 **이전 입력 가져오기**로 현재 소스가 지원하는 항목을 다시 가져올 수 있습니다. 가져오기는 미저장 편집 한 단계이므로 Undo로 취소할 수 있습니다. 지원되지 않는 항목은 안내하고 사본에 남깁니다.

1~3단계에 만들어 이력 기록이 없던 프로젝트는 현재 버전만 기준 버전으로 보여줍니다. 다음 정상 저장에서 그 기준과 새 버전을 함께 기록합니다. 과거에 별도로 기록하지 않았던 모든 수정 번호를 복원할 수는 없습니다.

## 검증 기록

검증은 로컬 브라우저 `http://127.0.0.1:5173/`와 루프백 서비스, 현재 Codex 대화의 실제 MCP 도구를 사용했습니다. 주 프로젝트 A는 `9059b75c-b3d2-4307-b64a-16060305e40d`이며 3단계의 저장 버전 11에서 시작했습니다. 마지막 저장본은 버전 16, 이미지 2개, 프레임 47입니다. 최종 버전 16의 소스·레이어 편집 값·파일 목록은 원래 버전 11과 JSON 비교로 일치함을 확인했습니다.

| 확인 | 현재 결과 |
| --- | --- |
| 입력 묶음·Undo/Redo·단축키 | 문구를 입력하고 초점을 옮긴 뒤 Undo 한 번으로 취소, Redo로 재적용. Ctrl+Z·Ctrl+Shift+Z 확인 |
| 드래그 한 번 → Undo 한 번 | 제목 위치 `(90.77, 178.77)` → `(123.08, 204.92)`. Undo 한 번으로 위치를 복구하며 앞서 수정한 문구 유지 |
| 저장 후 Undo/Redo | 저장 뒤 Undo는 미저장 표시, Redo로 저장 내용과 다시 같아지면 미저장 표시 해제 |
| 프로젝트별 초안·Undo·프레임 | A의 문구·위치·프레임 47 유지. B의 너비 `540 → 542 → Undo 540`이 A의 Undo와 분리됨을 확인 |
| 오프라인 새로고침·편집·재연결 | 서비스 종료 후 같은 탭 새로고침에서 A의 초안·위치·프레임 47 복구. 문구 추가 편집 가능, 재연결 후 입력 유지 |

| 현재 대화의 정상 소스 변경·충돌 비교 | 설명의 `fontSize` 지원을 제거한 소스를 버전 12로 반영. 브라우저 제목 문구·위치는 유지하고 최신본 적용 안내 후 저장 버전 13 확인 |
| 버전 복원·복원 전 초안 회수 | 임시 제목 초안을 보관하고 버전 11을 새 버전 14로 복원. 이전 입력 가져오기 후 미저장 상태, Undo로 저장 상태 복귀 |
| 미지원 입력 사본 보존 | 설명 글자 크기 23을 미저장 편집한 뒤 MCP로 해당 지원 제거 → 버전 15. 최신본 적용 시 경고와 사본 보관. 버전 14를 새 버전 16으로 복원한 뒤 이전 입력 가져오기에서 23 복구, Undo로 저장 값 19 복귀 |
| Undo 트랜잭션·취소·100개 제한 | 순수 이력 자동 검사 9개 통과. 포인터 취소 동작을 브라우저에서 직접 유발한 검증은 수행하지 않음 |
| 초안 비교·저장 후 추가 입력·미지원 속성·사본 격리 | 순수 초안 자동 검사 9개 통과 |

| 동시 편집 충돌 | 자동 검사에서 수정 번호 경쟁과 늦은 응답을 확인. 실제 두 번째 브라우저 탭을 동시에 편집하는 검증은 수행하지 않음 |

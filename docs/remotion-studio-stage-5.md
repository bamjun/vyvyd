# 포스터 메이커 5단계 — 출력·프로젝트 파일·이어 편집

작성일: 2026-10-04  
상태: 로컬 구현·파일 검증 완료 · 사용자 검토 대기

## 사용 흐름

포스터 메이커 아래 **포스터 출력**에서 PNG·GIF·MP4를 선택하고 출력 시작을 누릅니다. 출력에는 표시된 저장 버전을 사용합니다. 미저장 변경이 있으면 안내하며, 출력 중에도 캔버스를 편집할 수 있습니다. 작업 목록에서 진행률·대기·실패·취소 상태를 확인하고 취소한 작업을 같은 버전과 설정으로 재시도합니다.

완료된 작업의 **결과 보기**에서 미리보기·다운로드·이어 편집을 사용할 수 있습니다. PNG·GIF는 크기 줄이기·분할·합치기로 전달하고, MP4는 **영상 변환으로 보내기**로 전달합니다. 전달할 파일을 모두 읽고 도구에서 로딩을 마친 뒤 이동하며 기존 목록·설정을 유지합니다.

**프로젝트 파일 만들기**는 현재 저장 버전의 소스·이미지·레이어 값을 `.vyvyd.json` 하나에 담습니다. **프로젝트 파일 가져오기**는 새 ID·버전 1의 별도 프로젝트를 만듭니다. 현재 초안은 프로젝트별로 보관됩니다. 이력·출력 결과·MCP 요청 기록은 가져오지 않습니다. 소스 문법과 실행 오류는 가져온 뒤 기존 컴파일 화면에서 확인합니다.

## 형식과 실행

| 형식 | 설정과 결과 |
| --- | --- |
| PNG | 지정한 한 프레임, 원본 비율의 크기, 투명 배경 선택 |
| GIF | 전체 구간, 원본 FPS의 약수 중 전체 길이를 유지하는 FPS, 무한 또는 총 재생 횟수 |
| MP4 | H264, 원본 FPS·전체 길이, 짝수 가로·세로 |

투명 PNG는 프로젝트의 캔버스 배경만 투명하게 바꿉니다. 소스에 직접 넣은 불투명 배경·도형·이미지는 유지됩니다. GIF·MP4는 지정한 배경색으로 출력하며 소스에서 그 배경 값을 사용해야 합니다. 출력 크기는 원본 비율을 정확히 유지하는 정수 크기를 사용합니다. 원본·50%·25% 중 정수 크기가 되는 프리셋을 제공합니다.

출력 시작 전에 문서·소스·이미지 바이트를 작업 전용 디렉터리에 고정합니다. 정상 미리보기를 재사용할 때에도 소스·구성·편집 값이 일치하는지 확인합니다. 별도 Node Worker·Chrome·Remotion 인코더에서 실행하므로 기존 FFmpeg WASM 작업과 취소 범위를 공유하지 않습니다. 한 번에 출력 하나를 실행하고 최대 8개의 진행·대기 작업을 받습니다. 소스 준비 중 취소한 작업은 준비가 정리된 뒤 다음 작업을 실행합니다.

실패·취소된 작업은 고정한 소스와 파일에서 다시 실행합니다. 시작·재시도 요청 UUID를 보관해 응답이 끊긴 요청을 재확인해도 중복 출력하지 않습니다. 완료 파일과 작업 이력은 서비스 재시작 후 유지하며, 실행 중 중단된 작업은 재시도 가능한 실패로 표시합니다. 다운로드는 고정된 작업 ID 또는 프로젝트 저장 버전의 HTTP 파일 경로이며 미리보기·도구 전달용 Blob과 구분합니다.

출력은 최대 1,677만 픽셀·영상 18,000프레임·파일 512 MiB, 픽셀×프레임 예산으로 제한합니다. 프로젝트 파일은 이미지당 20 MiB·합계 100 MiB·최대 100개·JSON 전체 145 MiB입니다. 이미지 서명·Base64·SHA-256·경로·레이어 값을 검증하고 가져오기 실패 시 새 프로젝트만 정리합니다.

기본 보관 위치는 `.local/studio/projects/`, `.local/studio/previews/`, `.local/studio/exports/`이며 Git에서 제외합니다. 실행은 `npm run studio:server`와 `npm run dev`, 화면은 `http://127.0.0.1:5173/?studio=1`입니다.

브라우저에서 GIF 취소·같은 설정 재시도 후 완료를 확인했습니다. 취소한 작업의 파일 응답은 409이며 재시도한 600×800 GIF와 같은 설정의 완료 파일 바이트가 같았습니다. PNG·GIF를 크기 줄이기로 전달해 파일 2개·50% 설정이 유지됐고, MP4가 영상 도구에서 300×400·0~3초 구간으로 열렸습니다. 프로젝트 가져오기 후 정상 소스 미리보기를 확인했고 소스·편집 값·구성·파일 메타데이터와 이미지 바이트를 원본과 비교했습니다. 서비스 재시작·브라우저 새로고침 후 완료/취소 이력도 다시 표시됐습니다.

자동 검사는 테스트 236개 통과·선택 검사 1개 제외, lint·TypeScript·production build 통과입니다. 저장 버전 고정, 취소·재시도·재시작, 응답 순서 역전, Origin·프로젝트 접근 범위, 경로·파일 변조, 번들 손상·원자적 가져오기와 기존 도구 전달을 검사했습니다. 원본 서버 버전이 갱신된 뒤에도 고정 버전 프로젝트 다운로드가 같은 내용을 반환하는 HTTP 검사도 포함합니다.

증거는 `artifacts/studio-stage-5/validation.json`, `browser-output.jpg`, `image-transfer.jpg`, `video-transfer.jpg`, `bundle-import.jpg`, `browser-review.jpg`에 보관합니다. 내장 브라우저의 자동 다운로드 도구는 Blob과 HTTP 링크 모두에서 시간 초과가 났습니다. 세 파일과 프로젝트 번들은 실제 HTTP 파일 응답으로 저장·검사했지만, 내장 브라우저가 다운로드 클릭 후 디스크에 저장하는 동작은 확인하지 못했습니다. 분할·합치기 버튼은 기존 전달 계약을 사용하며 이번 수동 검증은 크기 줄이기와 영상 전달에 집중했습니다. 기존 WASM 변환과 Remotion 출력을 동시에 실행하는 수동 검사는 이후 전체 흐름 검증에 남겼습니다.

배포된 HTTPS 화면의 로컬 연결·다운로드와 전체 흐름은 6단계 검토 대상입니다. 이번 결과는 로컬 환경의 검증입니다.

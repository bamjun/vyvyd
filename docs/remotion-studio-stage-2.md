# 포스터 메이커 2단계 — 현재 Codex 연결

검증일: 2026-10-03  
상태: 로컬 구현·현재 대화 연결 검토 완료 · 사용자 승인에 따라 3단계 진행

## 확인할 결과

[포스터 메이커](http://127.0.0.1:5173/?studio=1)의 **단계 2 Codex 연결 포스터**, 프로젝트 ID `9059b75c-b3d2-4307-b64a-16060305e40d`를 확인했습니다. 이 문서의 버전 **6**과 화면·PNG는 2단계 당시의 검증 기록입니다. 같은 프로젝트는 이후 3단계 직접 편집을 거쳐 현재 검토 저장본이 버전 **11**이며, 최신 화면과 결과는 [3단계 기록](./remotion-studio-stage-3.md)에 있습니다.

현재 Codex 대화에 등록된 실제 `vyvyd-studio` MCP 도구로 프로젝트를 읽고 Remotion 소스를 수정했습니다. 결과가 vyvyd 안에 표시되고, 같은 도구로 PNG를 받아 시각적으로 확인했습니다. 별도 디자인 템플릿 없이 작성한 한글 포스터에 로컬 폰트·이미지·궤도 애니메이션을 넣었습니다.

## 사용 순서

1. 터미널에서 `npm run studio:server`로 로컬 서비스를 실행합니다. 기본 주소는 `http://127.0.0.1:4180`입니다.
2. 다른 터미널에서 `npm run dev`를 실행하고 포스터 메이커에서 프로젝트를 만듭니다.
3. 최초 한 번 `npm run studio:setup`을 실행합니다. 프로젝트의 `.codex/config.toml`에 로컬 stdio MCP 서버 설정을 추가하며 기존 설정을 유지합니다. 이 컴퓨터의 설정과 현재 대화 도구 등록은 확인했습니다.
4. 프로젝트의 **원하는 작업**에 요청을 적고 **프로젝트 요청 문구 복사**를 눌러 현재 Codex 대화에 붙여넣습니다. 프로젝트 ID와 저장된 수정 번호가 함께 복사됩니다.
5. Codex가 최신 프로젝트·소스·이미지·편집 값을 읽고 소스를 적용하면, 검증에 성공한 결과가 미리보기에 자동 반영됩니다.

새 환경에서 설정 후 도구가 목록에 나타나지 않으면 Codex의 프로젝트 MCP 연결을 갱신하거나 세션을 다시 열고 `studio_list_projects` 호출을 확인하세요. 등록 파일이 존재하는 것만으로 연결 완료라고 표시하지 않습니다. 브라우저는 로컬 서비스 연결, MCP의 최근 연결 확인, 마지막 도구 호출을 따로 표시합니다.

AI 요청은 현재 대화에서 처리합니다. 요청 복사 버튼은 대화를 자동 실행하지 않으며 별도 AI API 키를 사용하지 않습니다. [공식 Codex MCP 안내](https://developers.openai.com/codex/mcp)

## 추가한 연결 기능

| 도구 | 역할 |
| --- | --- |
| `studio_list_projects` | 저장된 프로젝트 ID·수정 번호 확인 |
| `studio_read_project` | 구성, 파일 목록, 레이어 정의, 직접 편집 값과 소스 읽기 |
| `studio_read_file` | 해당 프로젝트에 등록된 소스 읽기 |
| `studio_read_asset` | 해당 프로젝트의 이미지 확인 |
| `studio_apply_source` | 소스 여러 개·편집 값 일괄 검증 후 반영 |
| `studio_update_edits` | 등록된 레이어의 지원 속성·배경 수정 |
| `studio_add_image` | 이미지 파일 보관, 안정적인 파일 ID 반환 |
| `studio_validate_source` | 저장하지 않고 소스 초안 검증 |

수정에는 프로젝트 ID, 예상 수정 번호, 요청 ID가 필요합니다. 같은 요청 ID와 같은 내용의 재시도는 중복 저장·중복 이미지 추가를 만들지 않습니다. 다른 내용으로 요청 ID를 재사용하거나 오래된 수정 번호로 저장하면 거부합니다. 요청 기록은 프로젝트와 함께 저장돼 서비스 재시작 후에도 유지됩니다.

## 소스와 직접 편집 값

진입 파일은 `src/Root.tsx`이며 `registerRoot()`와 `Poster` composition을 사용합니다. 실행 시 `composition`, `backgroundColor`, `layers`, `assets`, `assetUrls`를 전달합니다. 코드의 `calculateMetadata`는 프로젝트의 크기·FPS·전체 프레임 수를 반영해야 합니다.

직접 편집할 요소는 `src/layers.json`에 안정적인 ID와 지원 속성·기본값을 등록합니다. 코드가 기본값 위에 `props.layers[id]`를 합쳐 표시합니다. 이미지는 `assetUrls[assetId]`로 참조합니다. 레이어를 삭제할 때 남은 직접 편집 값도 명시적으로 정리해야 합니다.

검토 포스터의 `headline`, `description`, `proof-image`는 이 규칙으로 등록했습니다. 문구 편집 값을 바꾼 후 소스를 두 차례 수정해도 편집한 제목·설명과 업로드한 이미지가 유지됐습니다. 레이어 목록·캔버스 드래그 UI는 다음 3단계입니다.

## 적용과 오류 복구

소스 초안을 별도 스냅샷에서 번들링하고 실제 Remotion 렌더러로 시작·중간·끝 프레임을 검증합니다. 프로젝트 설정과 렌더러가 선택한 composition의 크기·FPS·길이도 비교합니다. 모든 프레임을 전수 렌더링하는 검사는 아닙니다.

검증에 성공한 뒤에만 예상 수정 번호를 다시 확인하고 소스·편집 값을 함께 저장합니다. 컴파일 실패나 검증 중 다른 저장이 발생하면 기존 저장본을 덮어쓰지 않습니다. 브라우저는 마지막 정상 미리보기를 유지하면서 오류를 표시합니다. 컴파일은 별도 worker에서 실행해 서비스의 연결 확인과 상태 조회가 계속 응답합니다.

미리보기는 `allow-scripts`만 허용한 별도 iframe에서 실행합니다. 프로젝트 ID·버전·메시지 발신자를 확인하고, 버전별 소스·파일 스냅샷을 읽습니다. 소스 읽기와 이미지 읽기는 프로젝트 범위로 제한하며 Node 호스트 모듈과 인라인 번들러 로더는 사용하지 못합니다.

브라우저에 저장하지 않은 입력이 있는 동안 Codex가 갱신하면 충돌 안내를 표시하고 입력을 유지합니다. 사용자가 저장본을 다시 읽거나 자신의 입력을 유지한 채 최신 버전을 기준으로 이어갈 수 있습니다. 서비스 재시작 시 소스와 모든 편집 값·파일·구성이 일치하는 정상 스냅샷을 찾아 복원합니다.

## 다음 검토 범위

2단계 완료 기준인 현재 대화의 도구 호출 → 자유로운 소스 작성·수정 → vyvyd 반영을 로컬 환경에서 확인했고 사용자의 다음 단계 진행 승인으로 검토를 마쳤습니다. [3단계](./remotion-studio-stage-3.md)의 레이어 선택·이동·문구·이미지 직접 편집도 로컬 검증을 마쳐 사용자 검토를 기다립니다. 수정 이력과 Undo/Redo는 4단계, PNG·GIF·MP4 출력 UI는 5단계입니다.

배포된 HTTPS 화면과 로컬 서비스의 연결은 아직 성공 확인 전입니다. 전체 배포 흐름은 6단계에서 검증합니다. 기존 `ad-mage`의 템플릿·디자인·파일을 가져오지 않았습니다.
